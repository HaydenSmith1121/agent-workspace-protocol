# 规则接收与自动归位

安装 skill 或初始化工作区，不会创建一个后台文件监听器。它提供的是智能体在创建或
修改规则时应遵守的确定性约定。

## 哪些部分是自动的

当智能体已经读取工作区入口和规则正本后：

- 新增长期工作区规则时，先分类再写入；
- 修订正本，而不是创建平行副本；
- 必要时更新记忆索引和当前状态；
- 当变更影响结构、权威或长期取舍时，新增决策记录；
- 任务结束前，将 `90-temp/inbox/` 中仍有价值的内容移动到长期分类。

这些动作由智能体执行。skill 本身不能监听文件系统，也不能拦截智能体会话之外的
手动编辑。

## 归位表

| 新增内容 | 默认位置 | 权威性 | 必须更新 |
| --- | --- | --- | --- |
| 工作区长期规则 | `MEMORY/01-rules/<topic>.md` | 权威 | `MEMORY/README.md` |
| 目录、命名或分类规则 | `MEMORY/02-structure/` | 权威 | 结构说明和索引 |
| 当前事实或结论 | `MEMORY/05-state/current.md` | 派生摘要 | 链接正本 |
| 长期决策及理由 | `MEMORY/06-decisions/NNNN-<topic>.md` | 权威 | 决策索引 |
| 任务历史 | `MEMORY/03-sessions/YYYY-MM-DD-<topic>.md` | 非权威 | 必要时登记 |
| 需求、设计、规范或契约 | `10-docs/` | 批准后权威 | 相关索引 |
| 最终报告、导出物或演示文稿 | `40-deliverables/` | 派生输出 | 来源和状态 |
| 暂未分类的临时内容 | `90-temp/inbox/` | 非权威 | 分类或删除 |

## 为什么不能做成完全自动

文件可能由很多工具创建：

- IDE 编辑器；
- Shell 脚本；
- 同步工具；
- 人工操作；
- 尚未读取工作区规则的智能体。

只有最后一种情况能够直接遵循协议。其他情况需要人工迁移，或者由智能体先做一次
工作区审计。

## 如何提高可靠性

1. 将工作区适配器和规则正本提交到版本控制。
2. 在智能体任务开始时，明确要求它先读取入口文件和规则正本。
3. 定期检查链接、密钥和根目录杂项文件。
4. 每个规则只保留一个正本，不创建重复摘要。
5. 长期规则改变时，要求智能体同时更新索引和当前状态。

完整协议见
[规则正本](../../skill/agent-workspace-protocol/references/workspace-protocol.zh-CN.md)。
