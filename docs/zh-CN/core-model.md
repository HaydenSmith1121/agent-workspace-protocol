# 核心模型

## 问题

AI 工作区不只是一个文件夹树，而是一个上下文系统。

当需求、源码、原始数据、生成报告、会话日志、草稿和长期规则处在同一视觉层级时，
智能体只能猜测每个文件的含义。下一个智能体可能：

- 把前一个模型的输出当作需求；
- 因为看不到状态而继续执行过期规则；
- 在短地图足够时读取大量历史文档；
- 修改重复副本，导致正本继续漂移；
- 把所有文件都当作可总结内容，从而泄露凭证；
- 混淆代码变更和知识变更，但二者拥有不同负责人和发布流程。

本协议用显式上下文边界替代猜测。

## 四个问题

每个工作区都应让新智能体在修改前回答：

1. 什么内容是权威的？
2. 什么是输入，什么只是输出或历史？
3. 应该先读什么，什么时候可以停止？
4. 新信息应该写到哪里，如何登记，如何标记状态？

如果任何一个问题不清楚，工作区就还没有达到智能体可用状态。

## 六个不变式

### 1. 单一正本

长期信息只有一个正本位置。索引、摘要和入口文件链接到它，不复制完整规则。

### 2. 权威顺序明确

默认从高到低：

1. 用户当前指令；
2. 有效工作区规则；
3. 有效且权威的规范或契约；
4. 代码和可执行测试；
5. 报告、导出等派生输出；
6. 历史、草稿和归档。

低层级不能静默覆盖高层级。

### 3. 输出不是输入

模型生成的报告、表格、图表或摘要都是工件，不是要求。只有经过人工或正式流程明确
晋升后，它们才能成为输入。

### 4. 代码和知识职责不同

代码有构建和发布生命周期，知识有解释和决策生命周期。默认分开保存。知识层保存
仓库地图、用途、分支、入口文档和验证提交锚点，不复制代码。

### 5. 当前状态、决策和历史不同

- 当前状态回答“现在什么是真的”；
- 决策回答“为什么这样选择”；
- 会话回答“这次任务发生了什么”。

不要让长会话日志成为当前事实的唯一来源。将长期结论提炼到状态、规则或决策记录。

### 6. 渐进读取

入口文件负责导航，索引列出相关文件，详细文档只在任务需要时打开。这可以减少上下文
腐化，也让不同上下文窗口的模型都能使用同一工作区。

## 跨智能体适配器

不同工具读取不同文件：

- Codex 和多种智能体工具识别 `AGENTS.md`；
- Claude Code 使用 `CLAUDE.md`；
- Gemini CLI 使用 `GEMINI.md`；
- Cursor 使用 `.cursor/rules/`；
- GitHub Copilot 使用 `.github/copilot-instructions.md`。

如果每个适配器都保存一份完整规则副本，各工具最终会遵循不同版本。因此适配器只应
包含指向规则正本的简短指针。

## 哪些内容可复用

可复用的是模型和安装器，不是某个项目的记忆。

全局 skill 可以：

- 检查现有工作区；
- 初始化标准入口文件；
- 解释权威模型；
- 发现危险或模糊结构；
- 帮助将文件迁移到更清晰的分类。

全局 skill 不能：

- 携带项目凭证；
- 包含项目会话日志；
- 成为项目规则的正式存放位置；
- 在没有明确请求和备份路径时覆盖工作区。
